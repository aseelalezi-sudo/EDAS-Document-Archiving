## 2. المرحلة 1 — إغلاق بوابة الأمان (P0)

### H1 — `effect` ReDoS في شجرة `prisma`

**المشكلة:** `prisma@6.19.3` (وهو في `dependencies`) → `@prisma/config@6.19.3` → `effect@3.21.0` المصاب بـ `GHSA-7589-6fvf-x4pw` (High). بوابة `Audit production dependencies` في `.github/workflows/ci.yml` تستخدم `--omit=dev`، لذا ستفشل.

**الخيارات (بترتيب التفضيل):**

1. **Override نقطي (موصى به):** في `api/package.json` ضمن `overrides` القائم:
   ```json
   "effect": "^3.22.5"
   ```
   ثم `npm install --prefix api`، ويجب أن يثبت `@prisma/config` على `3.22.5`. آمن لأنه ترقية Patch/Minor داخل نفس الخط 3.x.
2. **نقل `prisma` إلى `devDependencies`:** يخفي الأداة من تدقيق الإنتاج، لكن الحاوية تحتاجها في `npx prisma migrate deploy` أثناء الإقلاع — يتطلب تعديل `api/Dockerfile` وتثبيت CLI بشكل منفصل. أعلى كلفة ومخاطرة.
3. **ترقية Prisma إلى إصدار يعتمد `effect` مرقَّعاً:** غير متاح حالياً (7.10.1 يثبّت `3.20.0`؛ 8 لا يزال RC).

**خطوات التنفيذ:**

1. أضف override `effect` ثم `npm install --prefix api`.
2. تحقق: `node -e "console.log(require('./api/node_modules/effect/package.json').version)"` → `3.22.5+`.
3. تحقق: `npm audit --omit=dev --audit-level=high --prefix api` → **0**.
4. شغّل `npm --prefix api run prisma:generate` + `npm --prefix api test` + `npm run api:build` للتأكد من سلامة Prisma.
5. **اختبار انحدار:** أضف خطوة CI تفشل إن عادت الثغرة (البوابة الحالية كافية)، وحدّث `README.md` و`docs/release-0.1.0.md` بالسبب الجذري والحل.

**معيار الإنجاز (DoD):** تدقيق الإنتاج للـ API = 0، وكل بوابات الـ API خضراء، و`prisma generate/migrate` تعمل.

**الكلفة:** منخفضة (≤ 30 دقيقة). **الخطورة:** منخفضة.

## 3. المرحلة 2 — جاهزية التشغيل (P1)

### M3 — تسليم تنبيهات Alertmanager

**الخطوات:**

1. اختر وجهة (Slack Webhook أو SMTP أو Webhook داخلي) عبر متغيرات بيئة، لا أسرار في Git.
2. أضف `receivers` فعلياً في `infra/monitoring/alertmanager.yml` مع `route.routes` حسب `severity`.
3. أضف سرّ/متغيراً في `docker-compose.yml` (profile observability) و`.env.example` (قيم وهمية).
4. تحقق: `amtool check-config infra/monitoring/alertmanager.yml` ثم `curl -X POST localhost:9093/-/reload` و`amtool alert add` تجريبي.
   **DoD:** تنبيه تجريبي يصل للوجهة ويظهر في `amtool alert query`.

### M4 — جدولة النسخ الاحتياطي وVersioning الإنتاجي

**الخطوات:**

1. أضف مثال جدولة (cron/systemd timer/K8s CronJob) في `docs/backup-restore.md` (لا كود داخل التطبيق).
2. وثّق بدقة أن Versioning وObject-Lock على مخزن الإنتاج مسؤولية المنصة، مع أمر تحقق (`aws s3api get-bucket-versioning`).
3. أضف فحصاً في `verify.sh` أو سكربت منفصل يتحقق من وجود نسخة خلال آخر 24 ساعة (RPO ساعة).
   **DoD:** إجراء موثّق قابل للنسخ + فحص RPO آلي.

### M5 — مزامنة التوثيق مع CI

**الخطوات:** عدّل فقرة `README.md` لتطابق الواقع: بوابة `--omit=dev` معيقة، والتدقيق الكامل استشاري، مع سبب `picomatch`/`effect` والحل.
**DoD:** لا تناقض بين README و`ci.yml` (مراجعة يدوية + grep).

### H2 — استقرار التغطية (مراقبة ← إصلاح عند التكرار)

**الخطوات:**

1. لا تغيير الآن (غير مُعاد إنتاجه حتمياً).
2. محلياً: استخدم Node 22 LTS (`engines` تسمح 20+؛ CI على 22).
3. إن تكرر: جرّب `pool: "threads"` أو `vmThreads` في `vitest.config.ts` (يقلل إنشاء 112 بيئة jsdom ويخفض 50% من الزمن).
4. أضف `retry: 1` **فقط** إن أثبت التحليل أن الفشل بيئي وليس منطقياً — وليس بديلاً عن الإصلاح.
   **DoD:** 5 تشغيلات متتالية كاملة بلا انهيار، أو إصلاح جذري موثّق.

## 4. المرحلة 3 — الأداء والديون التقنية (P2)

### M1 — ترقيم خادمي لقوائم التشغيل

**الخطوات:**

1. أضف حالة ترقيم لكل من السلة/الاحتفاظ/الموظفين (كما `docsPagesRef` للمستندات).
2. استبدل `loadAllPages` في `:318-330` بصفحة أولى + `loadMore`.
3. اختبر: `store-docs` يحمّل صفحة واحدة، و«تحميل المزيد» يجلب التالية، وإعادة التحميل بعد عملية تُبقي عدد الصفحات المحمّلة.
   **DoD:** زمن الإقلاع لا ينمو مع حجم المؤسسة، مع اختبارات تغطّي الحالتين.

### M2 — تحقق السلسلة بالدفعات

**الخطوات:**

1. حوّل `loadChain` إلى cursor على `seq` بدفعات (مثلاً 5,000) مع حالة تحقق متسلسلة.
2. ابدأ من آخر `baseline` لتقصير المسار.
3. اختبر بسلسلة كبيرة مُولّدة (أو mock) وبسلسلة بها كسر لاحق للتأكد من الاكتشاف.
   **DoD:** ذاكرة ثابتة تقريباً بغضّ النظر عن عدد الأحداث، مع نفس تقرير `verifyChain`.

### L4 — تنظيف التحذيرات

1. `api/vitest.config.ts` → `api/vitest.config.mts`.
2. خطة ترحيل `package.json#prisma` إلى `prisma.config.ts` (لا يُنفَّذ قبل Prisma 7).
   **DoD:** لا تحذيرات في مخرجات البوابات.

### L2 / L3 / L1

- `L1`: حذف المجلد الفارغ محلياً (غير متتبع).
- `L2`: ترحيل تدريجي لـ `L(ar,en)` إلى `src/i18n.ts`، ملف أو اثنان لكل PR، مع اختبار تطابق المفاتيح.
- `L3`: تفكيك `store-docs.tsx` إلى نطاقات (Documents / Governance / Directory) دون تغيير السطح العام.

## 5. البنود المغلقة كـ «غير موجودة» (لا تُعالَج)

| الادعاء                                      | سبب الإغلاق                                              |
| -------------------------------------------- | -------------------------------------------------------- |
| XSS من `dangerouslySetInnerHTML`             | 3 مواضع فقط، كلها `escapeHtml` + CSP `script-src 'self'` |
| توكينات في `localStorage`                    | الجلسة `httpOnly` فقط، لا أثر للتخزين المحلي             |
| وجود `any` / `@ts-ignore` / `eslint-disable` | 0 في الكود غير الاختباري                                 |
| مجلدات `api;C` و`.tmp-metrics-token;C`       | غير موجودة على القرص (أثر عرض سابق فقط)                  |
| إصلاح `effect` عبر `npm audit fix`           | مثبت بالدليل أنه غير كافٍ؛ يُستبدل بـ override           |
