# اختبار سعة الوثائق

يشغّل **Document load benchmark** على GitHub Actions نسخة معزولة من PostgreSQL وMinIO وKeycloak وواجهة EDAS API. يمكن تشغيله يدويًا من تبويب Actions وتحديد عدد العمال المتزامنين والمدة حتى 120 دقيقة. تعمل طلبات الدمج التي تغيّر إعداد الاختبار أو سكربتاته لمدة ثلاث دقائق للتحقق من المسارات. الإعداد الافتراضي مليون سجل وثيقة، موزعة على 16 قسمًا و256 مجلدًا، مع وثائق محذوفة وقواعد صلاحيات مختلفة.

يقيس السيناريو القائمة بحساب المدير والموظف، وصفحة قريبة من نهاية النتائج، والبحث العربي بحساب مقيّد، والتنزيل والمعاينة، ومسار الرفع حتى تسجيل الوثيقة. يسجّل التقرير عدد المحاولات والأخطاء وزمن الاستجابة للمئين 95 لكل عملية، وأقصى ذاكرة مقيمة لعملية API ومواصفات المشغّل. تبقى حدود زمن الاستجابة قرارًا مبنيًا على بيئة النشر وحملها المتوقع.

تستخدم سجلات الوثائق المزروعة ملف PDF مشتركًا. يضيف وضع التحمّل كائنات MinIO مستقلة للتنزيل والمعاينة، وينشئ ملف PDF جديدًا لكل عملية رفع بحمولة اصطناعية من 64 KiB إلى 12 MiB. يقارن الاختبار بصمات SHA-256، ويوزّع بدء العمال لتقليل الاندفاع، ويجدّد رموز الدخول قبل انتهائها. يعرض التقرير المحاولات والإخفاقات لكل دقيقة، وعدد البايتات التي جرى التحقق منها لكل عملية نقل. يُنشر التقرير ضمن آثار تشغيل GitHub باسم `edas-load-result`.

يقيس هذا الإعداد أثر مليون سجل وإصدار على PostgreSQL مع عمليات تخزين فعلية في بيئة معزولة. لاختبار سعة مليون كائن مستقل أو اعتماد حدود أداء للإنتاج، استخدم بيئة مماثلة لخادم النشر وأحجام ملفات وتوزيعًا يمثل الاستخدام الفعلي.

## فهرس البحث

تستخدم ترحيلات PostgreSQL إضافة `pg_trgm` وفهرس GIN لعمليات البحث الجزئي في حقول الوثيقة والبحث بالوسوم. يشغّل Prisma الترحيلات ضمن عملية النشر. عند استخدام حساب ترحيل بلا صلاحية تثبيت الإضافات، فعّل `pg_trgm` في قاعدة EDAS عبر مسؤول قاعدة البيانات قبل الترحيل. يُبنى الفهرس بالتزامن مع عمليات القراءة والكتابة.
