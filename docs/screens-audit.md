# خطة المرور على شاشات EDAS وفحصها وتطويرها

> مستند عمل حي. يُحدّث بعد كل جلسة فحص (الحالة، المشاكل، قرارات الإصلاح).

## 1. الهدف

الوصول إلى حالة يكون فيها **كل شاشة** في التطبيق:

1. تُفتح دون أخطاء (كونسول نظيف، لا استثناءات).
2. تعمل بالعربية (RTL) والإنجليزية (LTR) دون نصوص مبتورة أو مفاتيح ترجمة خام.
3. كل زر/رابط فيها يؤدي إلى **إجراء حقيقي** (قراءة/كتابة عبر `/api/v1`) أو يكون معطّلًا بوضوح مع سبب — لا أزرار «تُظهر إشعارًا فقط».
4. تعرض حالات: تحميل، فراغ، خطأ، ونجاح — وتعتمد بيانات حقيقية لا أرقامًا مُختلقة.
5. تحترم مصفوفة الصلاحيات (`ROLE_ACCESS` في `packages/shared` + `nav-config.ts`).
6. متاحة بلوحة المفاتيح ومقروءة لقارئ الشاشة (تسميات `aria-label`، عناصر تفاعلية حقيقية).
7. مغطاة باختبار على الأقل (وحدة/صفحة) عندما يكون السلوك غير بديهي.
8. موثّقة في هذا الملف بحالة نهائية ومشاكل معروفة (إن بقي منها شيء).
