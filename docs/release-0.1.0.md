## ملخص التغييرات (المصدر: `[Unreleased]` في `CHANGELOG.md`)

- **الصلاحيات والنطاق:** إنفاذ `Folder.scope` (`PUBLIC` / `DEPARTMENT` / `SECTION` / `PRIVATE`) مع ترحيل `Folder.sectionId`، وأذونات فعّالة على الخادم: سقف الدور + `DENY` يفوز دائمًا + `ALLOW` لا يتجاوز سقف الدور، وحارس `canManageAcl`، و`MANAGE_SCOPE` لتغيير النطاق أو الوراثة.
- **الرؤية:** قائمة المستندات وشجرة المجلدات تُشتقّ من الأذونات الفعلية بدلًا من ترشيح الإدارة وحده.
- **المعاينة:** طابور Redis/BullMQ اختياري مع إعادة محاولة ومعرّفات مهام ثابتة وبديل داخل العملية، وقائمة Windows في «مجلدات ODA».
- **المراقبة:** تتبّع OpenTelemetry وربط `traceId` بالسجلات، وملف اختياري لـPrometheus / Alertmanager / Loki / Promtail / Grafana / Collector / Jaeger.
- **الواجهة والوصولية:** ربط تسميات النماذج بـ`htmlFor`/`id`، وأسماء وصولية لعناصر التحكم الأيقونية، ومنع `employee` / `auditor` من `/dashboard/department`.
- **الإصلاحات:** سجل تشغيل التقارير، وتحذيرات ESLint، والرقم الوظيفي الخماسي، ومسارات ODA على غير Windows.

### البند 6 — مصفوفة ACL (سماح/منع/نطاق/وراثة)

تغطية `scripts/e2e.ps1`: تخزين قواعد `ALLOW`/`DENY` وإرجاعها، ورفض التأثير غير الصالح بـ`400 VALIDATION_ERROR`، و`403` للموظف خارج نطاق الإدارة، وقائمة مستندات مُنطَّقة تطابق ملخّص لوحة المعلومات، واختبار قبل/بعد قاعدة `DENY`. تُدعم باختبارات وحدة في `api/src/modules/folders`.

فحص حي على الستاك (SPA ↔ API ↔ Keycloak، عبر Bearer):

| الدور    | `/documents` | `/folders/tree` | `/users` | `/roles` | قراءة مستند إدارة أخرى |
| -------- | ------------ | --------------- | -------- | -------- | ---------------------- |
| admin    | 200 (24)     | 200 (14)        | 200      | 200      | 200                    |
| manager  | 403          | 403             | 403      | 403      | —                      |
| employee | 403          | 403             | 403      | 403      | 403                    |

المستخدمون موجودون في قاعدة البيانات بالأدوار (`SYSTEM_ADMIN` / `DEPT_MANAGER` / `EMPLOYEE`) لكن بلا `departmentId`، فنتيجة تقاطع النطاق فارغة → **رفض افتراضي**. `/metrics` يرجع `401` بلا رمز (`METRICS_TOKEN` مطلوب).

مقتطفات من تشغيل `e2e` الأخير على مرشّح الإصدار:

```
report.schedule.write: foreign=403 org-wide=403 run-foreign=403 admin=200
report.run.download:   foreign=403 own=200 admin=200
legal-hold.scope:      release=403 remove-foreign=403 remove-own=200 admin-release=201
org.scope:             top-level=403 foreign-child=403 foreign-edit=403 own=200
org.directory:         redacted=1 full=1
```

## المتبقي قبل الوسم

1. **موافقة مالك الإصدار** (البند 8) — إلزامية قبل أي وسم.
2. **قرار:** هل يُرفع حقل `version` في `package.json` (الجذر و`api/`) من `0.0.0` إلى `0.1.0` ضمن الإصدار؟
3. عند الاعتماد: نقل `[Unreleased]` إلى `## [0.1.0] - YYYY-MM-DD` في `CHANGELOG.md`، ثم `git tag v0.1.0` على كوميت الإصدار ودفعه مع فرع الإصدار.
4. بنود `docs/screens-audit.md` (المرحلة 10: سكربت الفحص الدائم، مسح i18n الكامل، فحص RTL/الداكن لكل شاشة، سيناريو E2E لكل دور) **ليست** مانعة للإصدار 0.1.0.
