# تقرير تقني مفصل — مشروع EDAS لنظام الأرشفة الإلكترونية

> **نطاق الفحص:** نسخة العمل الحالية على الفرع `master` (آخر commit: `31b6554`)، بما يشمل الواجهة، الـ API، قاعدة البيانات، البنية التحتية، الاختبارات، CI والتوثيق.
> **منهجية:** قراءة الكود والملفات الإدارية + تشغيل بوابات التحقق فعليًا + قياس التغطية والبناء. هذا تقرير الفحص الأولي قبل المعالجة؛ سجل التحديثات في القسم 17.

## 1) الخلاصة التنفيذية

**الحكم العام:** المشروع **ناضج هندسيًا** ويتجاوز بكثير مستوى النموذج الأولي العادي. الفصل بين الواجهة والخادم واضح، ومصفوفة الصلاحيات موحّدة، والمصادقة نُقلت إلى نمط BFF سليم، وسلسلة التدقيق مصممة بعناية، وبوابات الجودة كلها خضراء. لكنه **ليس جاهزًا للإنتاج كما هو** بسبب ثلاث فئات من القيود:

1. **قرارات منتج/أمن معلّقة:** خصوصًا دلالات قواعد ACL من نوع `ALLOW`، وعدم دخول `Folder.scope` في حساب الصلاحيات، وغياب سياسة CSP.
2. **قيود توسّع أفقي:** طابور المعاينة وكاش LibreOffice يعيشان داخل عملية API واحدة.
3. **تشغيلي:** لا نسخ احتياطي مجدول، لا تتبّع موزّع/APM، لا تسليم تنبيهات، ولا وسوم إصدارات.

## 2) ما هو المشروع؟

EDAS نظام أرشفة إلكترونية للوثائق بمستوى مؤسسي، يغطي:

- **الوثائق:** إنشاء، تعديل، إصدارات، نقل، أرشفة، حجز/إفراج، حذف/استعادة/إتلاف، توقيع، وإعلان سجل.
- **التنظيم:** إدارات، أقسام، موظفون، مشاريع، مجموعات، وشجرة مجلدات.
- **الحوكمة:** ACL لكل مجلد، سياسات احتفاظ، حجز قانوني، سلاسل اعتماد، مهام وإشعارات.
- **البحث والتقارير:** بحث متقدم/محفوظ، تقارير مجدولة وتصدير CSV/Excel/PDF عربي RTL.
- **التدقيق:** سجل أحداث متسلسل بـ hash مع نقاط أساس وتحقق.

يعمل المشروع في **وضعين**:

| الوضع                    | الشرط                                                                     | السلوك                                              |
| ------------------------ | ------------------------------------------------------------------------- | --------------------------------------------------- |
| **العرض المحلي Offline** | غياب متغيّرات `VITE_API_URL` / `VITE_OIDC_ISSUER` / `VITE_OIDC_CLIENT_ID` | مصادقة وهمية، بيانات في `localStorage`، كل شيء محلي |
| **الوضع المتصل**         | ضبط المتغيّرات الثلاثة                                                    | Keycloak + API + PostgreSQL + MinIO + معاينة حقيقية |

هذا التمييز مهم: **نشر الواجهة دون ضبط المتغيّرات يعني نشر وضع تجريبي مفتوح**، وقد وثّق المشروع ذلك بصراحة.

## 3) المعمارية العامة

```text
┌──────────────────────────┐
│  SPA — React 19 + Vite 7 │  HashRouter، RTL/LTR، وضعان
│  stores + pages + lib    │
└────────────┬─────────────┘
             │ httpOnly session cookie + CSRF header
             ▼
┌──────────────────────────────────────────────┐
│  API — NestJS 11                             │
│  JWT guard → Roles → Validation → Interceptor│
│  Modules: documents, folders, files, preview │
│  approvals, retention, reports, audit, users │
└───┬───────────┬───────────┬──────────┬───────┘
    │           │           │          │
    ▼           ▼           ▼          ▼
PostgreSQL   MinIO/S3   Keycloak    LibreOffice/ODA
 Prisma 6    كائنات      OIDC        تحويل معاينات
    │
    └────────► Prometheus /metrics + JSON logs
```

**تدفّق الدخول (BFF):**

1. المتصفح يفتح `/api/v1/auth/login` → الخادم يبني طلب Keycloak مع PKCE S256 ويضع `state`/`verifier` في كوكي موقّع.
2. Keycloak يعيد الكود إلى `/api/v1/auth/callback`.
3. الخادم يتبادل الكود، يخزّن الرموز **مشفّرة** في جدول `UserSession`، ويُصدر كوكي `edas_session` (httpOnly) وكوكي `edas_csrf` (مقروء).
4. كل طلب لاحق يمرّ عبر كوكي الجلسة + ترويسة `x-csrf-token` في الطلبات المعدِّلة.
5. المتصفح **لا يحمل أي توكن**؛ وهذا يعالج أخطر ثغرة كانت موثّقة في `AUDIT.md`.

## 6) الـ API (NestJS)

### 6.1 الأنماط المعمارية

- كل المسارات تحت `/api/v1`، والاستجابات بغلاف `{ data }`، والأخطاء `{ error: { code, message, messageAr, details }, correlationId }`.
- سلسلة المعالجة: `ThrottlerGuard` → `JwtAuthGuard` → `RolesGuard` → `ValidationPipe` (whitelist + forbidNonWhitelisted) → `TransformInterceptor` → `HttpExceptionFilter`.
- كل طلب يحمل `x-correlation-id` ويُسجَّل في JSON Logger.
- المقاييس تمر عبر `MetricsInterceptor` بمفاتيح `method`/`route`/`status`، مع `unmatched` للمسارات غير المطابقة.

### 6.2 توزيع الوحدات

| ---------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `auth` + `SessionModule`                             | BFF، Keycloak OIDC، جلسات مشفّرة، CSRF، تسجيل الخروج، تنظيف الجلسات                      |
| `users`                                              | إدارة الحسابات + مزامنة Keycloak Admin API (إنشاء/تعديل/قفل/حذف/إعادة تعيين/إلغاء جلسات) |

### 6.3 نقاط قوة

- فصل صريح للصلاحيات على الخادم، و`RolesGuard` + سياسات دور قابلة للتجاوز عبر `RolePolicy`.
- تحقق مدخلات صارم ورفض الحقول غير المعروفة.
- تدقيق إلزامي لكل عملية معدِّلة تقريبًا.
- معالجة سباقات حقيقية: قفل استشاري لسلسلة التدقيق، claim ذرّي لجدولة التقارير، و`UploadIntent` يمنع إعادة استخدام الرفع.
- رسائل خطأ عربية موحّدة (`error-reasons-ar.ts`) وأخرى إنجليزية.
- اختبارات 98%+ تغطي الخدمات والمتحكّمات والفلاتر والحُرّاس.

**ملاحظات تقنية:**

- 27 فهرسًا و60 علاقة، مع ترحيلات صريحة في `api/prisma/migrations` — لا `db push` في الإنتاج.
- `AuditEvent` يحتوي `seq` + `prevHash` + `hash` + `hashVersion`، وسلسلة التحقق تقرأ الأحداث وتكتشف الانقطاع/التشعّب/فقدان البصمة.
- `sizeBytes` من نوع `BigInt` في `FileObject`، ويُحوَّل في طبقة الـ DTO.
- `UploadIntent` يربط الرفع بالفاعل وينتهي بعد مدة، و`DownloadTicketUse` يضمن تسليمًا واحدًا عبر النسخ.
- `UserSession` مرتبط بـ `User.keycloakSub` مع `onDelete: Cascade`.
- seed المؤسسة idempotent ويشمل الإدارات والأقسام والموظفين والمشاريع والمجموعات والمجلدات والسياسات والسلاسل والإعدادات.

**نقطة ضعف محتملة:** التحقق من سلسلة التدقيق يقرأ السلسلة كاملة في الذاكرة؛ مع ملايين الأحداث سيصبح ثقيلًا ويحتاج ترقيمًا/تحققًا تدريجيًا.

### الثغرات/القيود الأمنية المتبقية

1. **قواعد ACL من نوع `ALLOW` تضيف قدرات فوق الدور**، وليس فقط ضمن سقفه. أي مستخدم لديه `EDIT` على مجلد يمكنه كتابة قاعدة تمنح نفسه `DELETE` أو `APPROVE` داخله. هذه **ثغرة تصعيد صلاحيات داخلية** ما لم يكن السلوك مقصودًا ومنضبطًا بعملية إدارة ACL منفصلة.
2. **`Folder.scope` (`PUBLIC/DEPARTMENT/SECTION/PRIVATE`) لا يدخل في حساب الصلاحيات**؛ الاعتماد حاليًا على `departmentId` + ACL فقط.
3. **لا توجد سياسة CSP** لأن `helmet` يعطّلها، والواجهة تعتمد على خطوط Google خارجية. XSS ممكن نظريًا، لكنه لم يعد يستطيع قراءة التوكنات.
4. **وضع العرض المحلي يقبل أي اسم مستخدم/كلمة مرور** عند غياب متغيّرات البيئة. يجب منع نشره في الإنتاج عبر فحص بناء/نشر صريح.
5. **`trust proxy 1`** يفترض قفزة بروكسي واحدة؛ أي توزيع مختلف قد يفسد بناء الروابط الآمنة أو IP.
6. **لا قيود على تسجيل الدخول على مستوى الحساب** (Lockout/Backoff) داخل الـ API؛ الاعتماد على Keycloak + throttler فقط.
7. **`METRICS_TOKEN`** إلزامي في الإنتاج لكنه غير مفعّل في التطوير (مقصود).

## 9) التخزين والمعاينة والتقارير

### 9.1 المعاينة

- PDF/صور/نص/DXF تُعرض من الأصل.
- Office (DOCX/XLSX/PPTX/ODT/…) يُحوَّل عبر **LibreOffice** إلى PDF.
- DWG يُحوَّل عبر **ODA File Converter** إلى DXF (اختياري).
- الكاش: `previews/<fileId>/<sha256>.pdf|dxf`، والتحويل يجري في طابور بحدّ تزامن ومهلة وسقوف حجم، مع بيئة مصغّرة ومجلدات مؤقتة تُحذف دائمًا. الطابور داخل العملية افتراضيًا، أو Redis/BullMQ عند ضبط `REDIS_URL`.
- التسخين المسبق `PREVIEW_PREWARM=on` يحوّل الملفات عند ربطها بوثيقة.
- الواجهة تستعلم حالة المعاينة حتى تجهز، وتعرض سببًا واضحًا عند فشل التحويل أو غياب المحوّل.

**القيد:** بدون `REDIS_URL` يبقى الطابور داخل عملية واحدة؛ الكاش في MinIO مشترك. عند التوسع اضبط `REDIS_URL` لتشغيل العمال عبر Redis/BullMQ.

### 9.2 التقارير

- 8 أنواع تقارير مبنية من قاعدة البيانات.
- تصدير CSV، Excel (SpreadsheetML)، وPDF عربي RTL بخط **Amiri** مع `bidi-shaper` و`pdfkit`.
- الجدولة تعمل بمؤقّت داخلي (60 ثانية افتراضيًا) مع **claim ذرّي** يمنع التشغيل المكرر بين النسخ.
- التنزيل عبر تذكرة مؤقتة، لا كشف مباشر لـ MinIO.
- فشل البناء/التخزين يُسجّل ويُبلَّغ عبر إشعارات.

### 9.3 الملفات

- مفاتيح التخزين: `documents/<year>/<uuid>.<ext>`.
- لا كشف مباشر لـ MinIO في المتصفح؛ الرفع presigned والتنزيل عبر تذكرة.
- فحص سلامة دوري: `GET /files/integrity` و`POST /files/:id/verify` و`POST /files/integrity/purge`.
- مفاتيح الكاش تجمع `fileId` + `checksum`، فلا تعارض بين ملفات متطابقة المحتوى.

## 11) CI/CD والنشر

### 11.1 خط أنابيب CI

خمس مهام في `.github/workflows/ci.yml`:

1. **SPA:** `npm ci` → audit → typecheck → lint → format → secrets → test:coverage → build.
2. **API:** تجميع `@edas/shared` → تثبيت → audit → Prisma generate → typecheck → lint → test:coverage → build.
3. **E2E:** بناء API + تشغيل Postgres/Keycloak/S3 mock عبر `scripts/e2e.ps1`.
4. **Docker:** بناء `api/Dockerfile` بـ buildx وكاش GitHub Actions.
5. **Browser:** تثبيت Chromium وتشغيل Playwright ورفع التقرير عند الفشل.

**جيد:** البوابات لا تسمح بتراجع التغطية، و`npm audit --audit-level=high` يمنع الثغرات العالية/الحرجة.
**ناقص:** لا توجد مهام نشر (deploy) أو توقيع صور أو فحص أمني للصور (Trivy/Grype) أو اختبار ترقية قاعدة بيانات على نسخة إنتاجية.

### 11.2 صورة الـ API

- بناء متعدد المراحل على `node:22-bookworm-slim`.
- LibreOffice + خطوط Noto/DejaVu/Liberation مثبتة مسبقًا.
- تشغيل بمستخدم `node` غير جذر.
- `prisma generate` أثناء البناء، و`npm prune --omit=dev` في مرحلة الإنتاج.
- أمر compose يشغّل `prisma migrate deploy` ثم `node dist/main.js`.

### 11.3 متطلبات الإنتاج

يرفض الخادم الإقلاع دون:

`DATABASE_URL`, `KEYCLOAK_ISSUER`, `KEYCLOAK_AUDIENCE`, `KEYCLOAK_ADMIN`, `KEYCLOAK_ADMIN_PASSWORD`, `MINIO_ENDPOINT`, `MINIO_BUCKET`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `CORS_ORIGINS`, `SESSION_SECRET`.

كما يرفض:

- `CORS_ORIGINS` تحتوي `*` أو `http://`.
- `SESSION_SECRET` أو `DOWNLOAD_TICKET_SECRET` أقصر من 32 حرفًا.
- أي كلمة مرور تطوير مثل `admin` أو `edas_dev_pw` أو `edas_minio_dev_pw`.
- `METRICS_TOKEN` قصير إن ضُبط.

**لا يوجد**: مدير عمليات، نشر متدرّج، فحص جاهزية تلقائي للترحيلات، أو خطة تراجع (rollback) آلية.
